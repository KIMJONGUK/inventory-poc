# issue-loop — 이슈 하나를 계약부터 리뷰까지 돈다

**한 줄:** 이슈를 받아 ① 관문 → ② 루프 열기 → ③ 구현 → ④ `npm run verify` → ⑤ PR → ⑥ CI → ⑥-b 리뷰까지 가고, **머지 앞에서 멈춘다.**

규칙의 원본은 `docs/harness/loop.md` · `ssot.md` · `verification.md` 다.
**이 스킬과 그 문서가 충돌하면 문서가 이긴다** — 고칠 것은 스킬이다. 여기 적힌 것은 절차뿐이고, 판단 기준은 전부 그쪽에 있다.

---

## 0. 하는 일 · 안 하는 일

| 한다 (AI) | 하지 않는다 (사람 몫) |
|---|---|
| 브랜치 · 커밋 · 푸시 · PR 열기·갱신 | **머지** — 승인이다 |
| 이슈 댓글로 회차·상태 기록 | `contract-draft` 떼기 · `계약 확정` 댓글 |
| `npm run verify` 실행 | **CI 재실행 버튼** |
| 코드 · 이 이슈의 새 테스트 작성 | 보호 영역 · 종료 조건 · 기존 테스트 기대값 |
| ⑥-b 리뷰 다섯 줄 달기 | 갈래 선택 (① 머지 · ② 다시 구현 · ③ 사람 판단) |
| `need-human` 라벨 붙이기 | 이슈 닫기 (⑧) |

오른쪽 칸을 하고 싶어지는 순간이 **멈춤 신호**다 (loop.md §3 경계).
`--no-verify`, 테스트 기대값 완화, 초록불 날 때까지 CI 돌리기 — 전부 판정을 AI 가 하는 것이다.

## 1. 대상 이슈를 정하고 상태를 복원한다

**다른 것을 보기 전에 이것을 먼저 돌린다.**

```bash
bash .claude/skills/issue-loop/scripts/loop-state.sh [이슈번호]   # 번호가 없으면 브랜치에서 찾는다
```

라벨 · `계약 확정` 여부 · 계약 6개 항목 · 상한 N · 상태 댓글 전부 · 마지막 `n/N` · PR · 브랜치 · 작업 트리를 한 번에 본다.
`gh issue view` 로 본문만 읽으면 **상태 댓글을 놓쳐 이미 끝난 루프를 처음부터 다시 구현**한다.
**세션이 끊겨도 여기서 복원된다** — 남는 것은 Issue 와 git 뿐이다 (loop.md §5).

**제목과 본문은 판정 근거가 아니다.** 초안으로 열린 이슈는 확정된 뒤에도 제목의 `[초안]` 과
본문 머리의 "라벨이 붙어 있는 한 열리지 않습니다" 가 잔존물로 남는다. 관문을 판정하는 것은
**라벨과 댓글**이다 (loop.md §4 — 상태의 원본은 댓글, 라벨은 색인).

| 받은 것 | 대상 |
|---|---|
| 이슈 번호·링크 | 그것 |
| 아무것도 없고 브랜치가 `issue-N-*` | N — **이어받기**다 |
| 아무것도 없음 | 열린 `maintenance` 이슈 중 `contract-draft`·`need-human` 없는 것. 하나면 그것, 둘 이상이면 **한 번 묻는다** |
| 해당 이슈가 없음 | 이슈를 만들지 않는다. 사람에게 알린다 (이슈 열기는 계약 초안 작업이다 — 다른 일) |

| 마지막 상태 댓글 | 한다 |
|---|---|
| 없음 | §2 관문부터 |
| `루프 시작 · 0/N` | n=0 을 이어받아 §4 |
| `루프 n/N · <실패>` | n 을 이어받아 §4 |
| `루프 n/N · 통과 · PR #x` | §7 CI 부터 |
| `LLM review` | **끝났다.** 사람의 갈래 선택을 기다린다 — 같은 초록불에 리뷰를 다시 돌리지 않는다 |
| `LLM review` + **PR 이 머지됨** | ⑦ 이 지나갔다. 남은 것은 ⑧ 이슈 닫기와 `선택 ①` 기록이고 **둘 다 사람 몫**이다. **머지 버튼을 사람의 선택 발언으로 내가 해석해 대신 적지 않는다** — 달아드릴까 묻고 멈춘다 |
| `선택 ② 다시 구현` | 사람이 골랐다 → §4 로. 고쳐서 verify 를 돌릴 때 n+1 |
| `선택 ①` · `선택 ③` | 루프는 닫혔다. 이어서 할 것이 있으면 새 Issue 다 |
| `NEED_HUMAN` | **답부터 찾는다.** 사람 답이 댓글로 와 있지 않으면 재시도하지 않는다 |
| `루프 종료` | 루프 밖이다. 새 Issue 없이는 아무것도 하지 않는다 |

## 2. 관문 — 열기 전에 네 개를 본다 (loop.md 부록)

멈춤선은 전부 "실패했을 때" 작동한다. 종료 조건을 잘못 읽으면 그 해석대로 테스트를 써서 **실패 없이 통과**한다. 그래서 상한을 받기 전에 먼저 본다.

| 관문 | 기계적 판정 | 못 넘으면 |
|---|---|---|
| **확정** | `contract-draft` 라벨이 없고 `계약 확정` 댓글이 있다 | 멈춘다. **라벨은 AI 가 떼지 않는다** — 떼면 계약을 AI 가 정하는 것이다 |
| **해석** | 종료 조건 한 줄로 참/거짓을 가를 테스트를 **한 가지로** 쓸 수 있다 | `NEED_HUMAN · 모호 · 0/N` |
| **1:1** | 계약 3번 네 줄 ↔ 4번 테스트 이름이 라벨·순서까지 1:1 | `NEED_HUMAN · 모호 · 0/N` |
| **충돌** | 이슈와 SSOT · 문서끼리 어긋나지 않는다 | `NEED_HUMAN · 충돌 · 0/N` |

6개 항목 중 비는 것이 있으면 시작하지 않는다 (ssot.md §4). 빈 계약뿐 아니라 **두 갈래로 읽히는 계약**도 시작하지 못한다.

**「해당 없음」 축** — 계약 3번과 4번이 **같은 라벨에서 같은 말로** 「해당 없음」이면 그 축은
판정 대상이 아니다 (#5 선례 — 읽기 전용 조회라 거부할 입력이 실제로 없었다).
한쪽만 「해당 없음」이면 그건 1:1 관문 실패다. §6 진입 조건의 "붙은 테스트가 실제로 존재"도 그 축은 세지 않는다.
**빈 축을 메우려고 계약 4번에 없는 테스트를 만들지 않는다** — 계약 밖 테스트를 AI 가 만드는 것이다.
이 자리는 `ssot.md` §4(「거부는 지정 에러를 던진다로 판정한다」)가 비워둔 곳이라 선례로 서 있다 —
또 걸리면 문서에 올릴지 사람에게 묻는다.

문서는 `AGENTS.md` 라우팅 표대로 읽는다 — `docs/harness/ssot.md` 하나로 답이 나오면 **거기서 멈춘다**. 전체를 한꺼번에 열지 않는다.

`NEED_HUMAN` 을 낼 때는 **질문 하나로 좁히고**, 답에 걸리지 않는 일은 다 해놓고 넘긴다. 양식은 `references/comments.md`.

## 3. 루프를 연다

상한 N = 계약 6번. 비어 있으면 ssot.md §7 의 전역 기본값(3). **N 을 모르면 시작하지 않는다.**

```bash
git switch main && git pull --ff-only
git switch -c issue-<N>-<슬러그>     # 예: issue-5-expiry-page. 이미 있으면 switch 만
```

그리고 **댓글이 먼저다** — 코드보다 먼저 남긴다. 다음 세션의 기준점이 여기서만 나온다.

```
루프 시작 · 0/3
계약: 종료 조건 4줄 · 판정 npm run verify
```

## 4. 구현 — 코드만 고친다

- **Next.js 16 은 아는 그 Next 가 아니다.** 코드를 쓰기 전에 `node_modules/next/dist/docs/` 의 해당 가이드를 읽는다 (CLAUDE.md)
- 계약 2번이 지목한 자리부터 고친다. 벗어나야 하면 **PR 본문과 이슈 댓글에 자진 신고**한다 (#5 선례 — `lib/expiry.ts` → `lib/inventory.ts`). 계약 5번을 침범해야 하면 그건 **경계**고, 신고가 아니라 멈춤이다
- 테스트는 계약 4번의 이름 그대로 만들고, **종료 조건 문장을 판정**하게 쓴다. 구현을 보고 거꾸로 쓰면 무엇을 해도 통과한다 — ⑥-b 가 정확히 이것을 본다
- 날짜는 `src/lib/date.ts` 의 `today()` · `addDays()`. 시드 숫자를 종료 조건이나 기대값에 박지 않는다 (시드가 바뀌면 깨진다)
- 조건부 `expect` 를 쓰지 않는다 — 씨앗이 바뀌면 소리 없이 사라지는 검사가 된다
- 부분 실행(`npm run typecheck` · `npx vitest run tests/x.test.ts`)은 **0회차**다. 마음껏 쓴다

## 5. 검증 = 회차 (verification.md · loop.md §2)

`npm run verify` 한 번이 **1회**다. prepare → types → lint → test → build 중 **어디서 깨져도 똑같이 1회**.

- **통과** → §6. 통과 뒤 재실행은 0회다
- **실패** → 멈춤선 셋을 먼저 보고, 아니면 댓글 달고 다시 §4

| 멈춤선 | 조건 | 토큰 |
|---|---|---|
| **반복** | 같은 단계 · 같은 원인 **2회 연속** — 횟수가 남아도 멈춘다 | `NEED_HUMAN · 반복 · n/N` |
| **총량** | n 이 N 에 닿았다. "한 번만 더"는 없다 | `NEED_HUMAN · 소진 · N/N` |
| **경계** | 고칠 대상이 보호 영역 · 종료 조건 · 기존 테스트 기대값 | `NEED_HUMAN · 경계 · n/N` (**0회차에도**) |

소진의 기본 해석은 **"계약이 틀렸다"** 다. 코드를 더 미는 것이 아니라 계약을 고칠지 묻는다 — 이때는 시도 전부와 각각 왜 실패했는지를 적는다.

**코드를 안 고치고 재실행하면 즉시 멈춤**이다. 재현되지 않는 실패를 눈감는 것이다.
실패 회차마다 댓글 하나 — 회차를 첫 줄에 박는다. 양식은 `references/comments.md`.

## 6. 제출 — 셋 다 참일 때만 PR 을 연다

| 진입 조건 |
|---|
| 로컬 `npm run verify` 통과 |
| 종료 조건 네 줄이 전부 참 — **각 줄에 붙은 테스트가 실제로 존재** |
| 이슈 댓글이 최신 (`루프 n/N`) · PR 번호를 함께 적는다 |

통과하지 못한 채 PR 을 여는 것은 판정을 사람에게 떠넘기는 것이다.

```bash
# 커밋 메시지와 PR 본문은 스크래치패드에 쓴다 — 저장소 안에 쓰면 그 파일까지 커밋에 딸려 들어간다
git add <이슈 범위 안의 경로만>          # git add -A 를 쓰지 않는다
git commit -F <스크래치패드>/commit-msg.txt
git push -u origin issue-<N>-<슬러그>
gh pr create --title "<한 줄> (#N)" --body-file <스크래치패드>/pr-body.md
```

**작업 트리에 이슈 범위 밖 변경이 있으면 커밋에 넣지 않는다.** `loop-state.sh` 가 찍어준 작업 트리
목록을 계약 2번과 대조한다. 문서 · 하니스 · 다른 스킬 같은 루프 밖 변경이 이슈 PR 에 섞이면
그 PR 이 무엇을 만족시켰는지 판정할 수 없고, "루프 밖은 main 직접 푸시" 규칙을 스스로 깨는 길이다.

- 커밋 제목 `<type>: <무엇을 한다> (#N)`, 본문에 **왜 · 무엇 · 계약 이탈**. 끝줄은 `Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>`
- PR 본문은 `.github/pull_request_template.md` 를 채운다. `Refs #N` 을 쓰고 **`Closes` 를 쓰지 않는다** — 머지가 이슈를 자동으로 닫으면 ⑧ 이 사람 몫이 아니게 된다
- **PR 에 커밋을 더할 때도 같다** — CI 로 가는 모든 코드가 로컬 verify 를 먼저 거친다. 이 줄이 없으면 고친 코드를 밀어 CI 만 다시 돌리는 길이 한 회차도 쓰지 않고 열린다
- 문서 · 계약 · 하니스만 고치는 변경은 **PR 이 아니라 main 직접 푸시**다 (loop.md §6). 닫을 루프가 없는 변경에 PR 을 씌우면 작성자와 승인자가 같아진다

## 7. CI — 한 번 기다린다

```bash
bash .claude/skills/issue-loop/scripts/ci-wait.sh       # 인자 없으면 HEAD
```

오래 걸리면 `run_in_background: true` 로 띄우고 결과를 읽는다.

| 결과 | 한다 | 회차 |
|---|---|---|
| 통과 | §8 | — |
| 실패 · **로컬에서 재현됨** | §4 로 돌아가 고친다 | CI 실패 자체는 **0회**. 고쳐서 verify 를 돌릴 때 n+1 |
| 실패 · **재현 안 됨** | `NEED_HUMAN · 환경 · n/N` | 쓰던 회차 |
| 취소 (새 커밋이 앞질렀다) | 새 SHA 로 다시 기다린다 | 0회 |

**이미 머지되거나 닫힌 PR 의 커밋으로는 돌리지 않는다** — 기다릴 run 이 없다. 그건 §1 에서 이미 갈린다.
**재실행 버튼은 누르지 않는다.** `protected-areas` 잡의 경고는 막지 않는 것이 정상이다 — 떴으면 사람에게 그대로 전한다. 승인은 PR 리뷰에서 난다.
**CI 결과를 확인하기 전에 루프를 닫지 않는다.**

## 8. ⑥-b LLM review — 판정이 아니라 자문

CI **통과 1건당 한 번**. CI 가 실패하면 돌리지 않는다(갈래가 이미 갈렸다). 회차를 쓰지 않는다. 무시하고 머지해도 규칙 위반이 아니다.

**별도 컨텍스트로 돌린다.** 요건은 하나다 — **내 문맥을 물려받지 않는 방식**으로 새로 띄운다.
구현하며 세운 합리화가 넘어오면 리뷰가 아니다. 지금 세션에서 쓸 수 있는 수단과 프롬프트,
그리고 왜 문맥을 이어받는 방식(`fork` 류)을 쓰지 않는지는 `references/review.md` 에 있다 — 열어서 그대로 쓴다.

**권고는 지시가 아니다.** `① 머지` 를 받아도 머지하지 않는다. 리뷰가 남긴 관찰(조건부 `expect` 같은 것)도
**곧바로 고치라는 지시가 아니다** — 루프가 닫힌 뒤에 고치려면 새 Issue · 새 계약 · 새 상한이다 (loop.md §1 · §3-2).

받은 다섯 줄을 **이슈 댓글에 단다(원본)**. PR 코멘트는 복사다. CI 잡으로 만들지 않는다 — 잡이 되면 자문이 게이트로 변한다.

## 9. 멈추고 넘긴다

리뷰를 달면 내 일은 끝이다. 마지막 보고에 이것만 적는다:

- 이슈 · PR 링크, 쓴 회차 `n/N`, 리뷰 권고
- **사람이 고를 갈래 셋** — ① 머지 · ② 다시 구현 · ③ 사람 판단 (loop.md §6)

**이미 머지된 이슈에 다시 "이슈 처리해줘" 가 오면** 재개가 아니다 — §1 표의 「PR 이 머지됨」 행으로 간다.
남은 ⑧ 을 사람에게 청하고, 고칠 것이 있으면 새 Issue 를 권한다. 같은 계약으로 상한을 늘려 재개하지 않는다.

머지하지 않고, 이슈를 닫지 않는다. `선택 ② …` 댓글은 **사람이 고른 뒤 그 말을 받아** 적는다 — 선택은 사람 머릿속에만 남으므로 기록은 남기되, 고르는 것은 사람이다.
